# RAG 知识库问答系统 — 100人并发压力测试方案

## 一、背景与目标

### 1.1 为什么需要压力测试

代码审查已发现 **12 个潜在性能瓶颈**（详见下文第三节），这些问题在单用户场景下完全不可见，但在 100 人同时使用时可能引发：

- SQLite 写冲突导致消息丢失
- 限流器竞态条件导致限流失效
- 百炼 API 频率限制导致大面积请求失败
- BM25 全局缓存被并发请求破坏

### 1.2 测试目标

| 指标 | 目标值 | 说明 |
|------|:---:|------|
| **并发用户数** | 100 | 模拟同时在线使用 |
| **RAG 查询 P95 延迟** | ≤ 30s | 含 LLM 生成时间 |
| **缓存命中 P95 延迟** | ≤ 2s | 相同问题走缓存 |
| **错误率** | ≤ 5% | 不含百炼 API 自身限流 |
| **吞吐量** | ≥ 10 QPS | 系统稳定处理能力 |
| **SQLite 写冲突率** | ≤ 1% | busy_timeout 调优后 |

## 二、工具选型

### 2.1 主工具：Locust

| 维度 | 选型理由 |
|------|---------|
| **语言** | Python 原生，与后端技术栈一致 |
| **异步支持** | 原生 `asyncio`，可复用项目已有的 AsyncOpenAI 客户端 |
| **Web UI** | 自带实时监控面板（RPS、响应时间百分位、错误率） |
| **脚本灵活** | 直接用 Python 写测试场景，可以调用 JWT 签发、数据库操作等 |
| **分布式** | 支持 master-worker 模式，单机不够时可扩展到多机 |

### 2.2 辅助工具

| 工具 | 用途 |
|------|------|
| **psutil** | 监控 CPU / 内存 / 磁盘 I/O（Python 原生） |
| **pytest + asyncio.gather** | 小规模并发正确性验证（不依赖 Locust） |
| **SQLite CLI / DB Browser** | 压测后检查数据库完整性 |

### 2.3 为何不用 k6 / Artillery

- k6 用 Go + JS 脚本，无法复用项目已有的 Python JWT 签发和 API 客户端
- Artillery 用 YAML 配置，表达能力不足以描述 SSE 流式解析 + 多步骤场景
- Locust 可以直接 `from app.services.auth_service import ...` 复用业务代码

## 六、Mock 模式设计

由于真实压测依赖百炼 API（有费用 + 限流），需要一个 Mock 模式来测试系统自身的并发上限。

### 6.1 实现方式

在 `backend/app/config.py` 中已添加：

```python
STRESS_TEST_MOCK: bool = False  # True 时跳过所有百炼 API 调用
```

### 6.2 Mock 行为

| 组件 | 原行为 | Mock 行为 |
|------|--------|----------|
| `llm_client.chat_completion_sync` | 调用百炼 LLM | `asyncio.sleep(0.05)` + 返回固定文本 |
| `embedding.embed_texts` | 调用百炼 Embedding | 返回固定 1024 维向量 |
| `reranker.rerank` | 调用百炼 Rerank | 返回前 k 个 + 递减分数 |
| `auto_generate_title` | 额外的 LLM 调用 | 直接用问题截断为标题 |

### 6.3 开关方式

```bash
# 真实模式（默认）
uvicorn app.main:app --port 8000

# Mock 模式（压测用）
STRESS_TEST_MOCK=true uvicorn app.main:app --port 8000
```

## 十、预期风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|:---:|------|------|
| **百炼 API 限流** | 高 | 大量请求返回 429/503 | Mock 模式下测试系统自身瓶颈；真实模式用小用户量 |
| **SQLite 写冲突** | 高 | 消息保存失败 | ✅ 已加 `busy_timeout` |
| **`_sync_embed` 阻塞** | 高 | 检索串行排队 | ✅ 已改为直接 await |
| **bcrypt 阻塞事件循环** | 高 | 登录风暴时 CPU 堆积 | 多 worker 分散 |
| **diskcache SQLite 写锁竞争** | 中 | 限流器/cache 变慢 | ✅ 已改为原子 incr；监控 P99 尖刺 |
| **ChromaDB 锁竞争** | 中 | 检索变慢 | 监控 ChromaDB 查询耗时 |
| **内存泄漏** | 低 | 长时间运行后 crash | 场景 7 浸泡测试可发现 |
| **Windows 文件句柄耗尽** | 中 | 无法打开新文件 | uvicorn worker ≤ 4 |
| **diskcache 损坏** | 低 | 缓存/限流失效 | 压测前后清理 `data/cache/` 目录 |
| **百炼 API 费用超预期** | 中 | 账单超标 | 严格用 Mock 模式；真实测试封顶 5 用户 × 3 分钟 |
| **WAL 文件失控增长** | 中 | 磁盘占满 | 场景 7 监控 WAL 大小 |
